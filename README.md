## 1. 项目简介
### 1.1 产品定位
**此刻地图** 是一款基于地理位置的实时社交工具。它以"地图"为界面、以"气泡"为语言——用户可以在当前位置发布即时信息（求助、组队、推荐、避雷、见闻、建群等），同一时空下附近的人可以即可看到并回应。根据气泡发布者设置的存留时长不同，用户也可以看到一段时间之前发布的气泡。

### 1.2 与现有工具的差别
| 工具 | 局限 | 此刻地图 |
| --- | --- | --- |
| **小红书 / 微博** | 内容是过去式的攻略，无法满足"此刻此地"的需求 | 信息按地理位置锚定在地图上，时效性强 |
| **微信群 / QQ群** | 信息容易淹没，建群流程繁琐，难以匹配到现场的人 | 一键建群气泡，无需加好友即可入群 |
| **高德 / 大众点评** | 静态的地点信息，缺少现场动态与同好连接 | 气泡带位置、带类型、带互动，现场动态实时更新 |

### 1.3 产品创新亮点
| 维度 | 传统方案 | "此刻地图"方案 |
| --- | --- | --- |
| **连接中介** | 用户↔用户直接匹配（如探探/陌陌） | 用户↔场景↔用户：以具体活动/地点为中介，破冰成本低 |
| **范围可视化** | 隐藏参数，用户无感知 | 实时圆圈可视化，随位置/范围动态变化 |
| **信息时效性** | 信息永久存在，历史内容干扰 | 气泡设有有效期，过期自动消失 |
| **群聊创建** | "建群"气泡即聊天室入口，点击即进入，无用即解散 |
| **信息分发** | 瀑布流 + 算法推荐 | 地理围栏 + 标签筛选，用户主动选择 |
### 1.4 设计理念
#### 「此刻即响应」
- 技术上，**WebSocket 全双工长连接**，新气泡、新消息的推送延迟控制在秒级
- 功能上，摒弃"瀑布流"信息轰炸，以**地理围栏 + 时效性**作为信息分发基础
- 你看到的永远是**此刻、此地、与我相关**的动态
#### 「地图即界面，气泡即语言」
- 用大众熟悉的地图作为主视觉，零学习成本
- 快速完成发布，浏览信息像查看地图标注一样简单
- 表达、求助、组队、分享，都通过这张"活的地图"发生

## 2. 商业调研

### 2.1 项目核心
**此刻地图**是一个**基于地理位置的线下实时社交与信息平台**。它以地图为界面，让用户可以在特定位置发布"气泡"（类似于帖子），用于**组队、求助、推荐、分享见闻**等。
**核心机制：**
- **地图为底，气泡为载体**：信息直接锚定在真实的地理位置上。
- **地理+标签双重筛选**：用户可选择可见范围（如500米内），并按活动类型筛选信息，保证信息精准、不打扰。
- **即时互动**：可对气泡进行评论、私聊，或一键进入"建群"气泡的临时聊天室，实现秒级组队沟通。
- **时效控制**：气泡可设置有效期，过期自动消失，确保信息"此刻"有用。
**一句话定位：** 让你在各种现场（音乐节、展览、校园、商圈），能随时找到同好、组队拼车、分享攻略的**实时地图**。
### 2.2 开发意义
项目精准切入了一个巨大的市场空白：**用户从"计划出行"到"事后分享"的环节已被各类App满足，但"正在现场"这个最需要即时信息和社交的环节，却没有任何高效工具。**
它主要解决了用户在参与线下活动时的四大核心痛点：
1. **临时组队难**：想找看展、拼车、拼饭的同伴，只能靠效率低下的微信群或跨平台的帖子。
2. **现场信息差**：哪个摊位最火？哪个队伍最短？厕所怎么走？这些即时信息无从得知。
3. **即时求助无门**：东西丢了、需要充电宝，身边全是陌生人，求助效率极低。
4. **同好难觅**：明明身边都是喜欢同一支乐队的人，却只能各自沉默，无法连接。
**项目问卷数据显示**：超过80%的受访者存在上述即时社交需求，证明这是一个真实、普遍且未被满足的市场。
### 2.3 实用价值
**对C端年轻用户（18-35岁大学生、白领、潮流爱好者）：**
- **高效连接**：秒级找到拼车、逛展、看演出的"搭子"。
- **真实情报**：获取第一手的现场"推荐"与"避雷"信息，不做"攻略受害者"。

- **安全保障**：在需要帮助时（如夜间独自回家），能快速向附近的人发出安全请求。
- **专属记忆**：通过"私密气泡"记录个人足迹和回忆，形成自己的"城市日记"。

**对B端商家与活动方（商圈、市集、音乐节主办方）：**
- **互动营销工具**：发布官方气泡，发起打卡挑战，与现场用户实时互动，提升参与感。
- **数字化运营**：获取活动现场的匿名化热力图、用户兴趣标签等数据报告，辅助决策，优化服务。
- **精准引流**：向特定场景下的高意向用户推送活动信息，实现从"泛曝光"到"精准触达"。

**对G端公共部门（远期潜力）：**
- **城市活力观测**：在合规前提下，提供脱敏后的城市人群流动、活动热点数据，辅助文旅规划与公共资源配置。

### 2.4 商业模式

项目规划了清晰、分阶段的多元化盈利模式，风险分散且增长路径明确。

| 阶段 | 核心收入来源 | 说明 |
| :--- | :--- | :--- |
| **前期 (0-12月)** | 少量B端合作试水 | 以验证模式为核心，向合作方收取象征性费用（如定制气泡、基础数据报告），不与巨头正面竞争，聚焦校园等细分场景。 |
| **中期 (12-24月)** | **C端虚拟商品 + B端商家认证** | - **C端**：出售气泡皮肤、头像挂件等个性化装扮。<br>- **B端**：向商家收取年度认证费、软件服务费，并提供进阶数据分析面板。 |
| **后期 (24月以上)** | **广告 + 数据服务 + 会员订阅 + 交易佣金** | - **广告**：在保证体验前提下引入激励视频广告。<br>- **数据服务**：向大型企业或政府机构销售城市级洞察报告。<br>- **会员**：提供包含所有特权的打包订阅服务。 |

**财务预测摘要（基于保守估计）：**
- **启动资金**：仅需5万元，依托学生团队和免费云资源，资金效率高。
- **盈利路径**：预计在第16-18个月实现**盈亏平衡**，第二年盈利7.2万元，第三年收入有望突破90万元。
- **核心逻辑**：前两年不追求盈利，专注于在核心场景（大学、商圈、市集）建立用户密度和社交网络效应。

### 2.5 优势总结

- **模式创新**：不是"找人"，而是"找场景"。连接因"同一现场的具体事件"而起，破冰成本远低于传统LBS社交软件。
- **定位精准**：避开巨头们追求"大而全"的战场，深耕"现场"这个细分但高频的蓝海市场。
- **需求刚需**：解决了80%线下活动参与者都遇到过的真实痛点，用户使用意愿强烈。
- **路径清晰**：从校园单点验证，到城市复制，再到生态构建，每一步都聚焦"密度先行"，风险可控。

**总而言之，"此刻地图"并非又一个试图取代微信或高德的工具，而是一个针对特定场景、解决特定痛点的"体验增强型"产品。它填补了人们在现场互动时的工具空白，具备扎实的社会价值、清晰的商业模式和可观的增长潜力。**

项目目录附有演示视频

初次使用只需三步：

1. **注册账号**：打开页面 → 点击右上角 **登录/注册** → 输入手机号 + 密码 → 完成注册

3. **看看附近**：地图上已有的彩色图标就是附近的人发布的**气泡**。点击任意气泡查看详情、互动。

### 3.3 发布一个气泡

从打开地图到成功发布，**只需 4 步**：

1. 选定你的中心位置（默认 GPS，可搜索切换）
2. 点击发布气泡按钮
3. 选气泡类型（6 选 1，必选）、填标题/正文/图片、选气泡留存时长
4. 点击发布

> 气泡有效期一到，**自动从地图上消失**，不会留陈旧信息。

### 3.4 气泡：6 种类型

发气泡时，必须从以下 6 种类型中**选择 1 个**：

| 图标 | 类型 | 适用场景 |
| --- | --- | --- |
| 🆘 | **求助** | 丢失物品、求充电宝、紧急情况 |
| 🤝 | **组队** | 拼车、拼桌、拼场地、需要同行者 |
| 💬 | **建群** | 想就地建一个临时聊天室 |
| ⭐ | **推荐** | 这家店不错、这个摊位很值、这个机位好看 |
| ⚠️ | **避雷** | 这里排队太长、这家踩雷、注意安全 |
| 👀 | **见闻** | 偶遇精彩瞬间、想分享此刻感受 |

- **图片**：最多可附 1 张图
- **有效期**：5分钟 / 30分钟 / 1小时 / 3小时 / 24小时 / 48小时
- **隐私**：设为"公开"则所有人可见；设为"私密"则仅自己可见且**永久保存**（不受时效影响），适合记录足迹、纪念日打卡、个人心情

### 3.5 建群气泡：一键开一个临时聊天室

> 这是"此刻地图"最独特的玩法。

1. 发布气泡时选 **建群** 类型，填好聊天室名称（如"草莓音乐节 D3 出口一起拼车回市区"）
2. 发布后，这个气泡**本身就是聊天室入口**
3. 任何看到气泡的人，**无需加好友、无需群主审核**，点击即进入聊天
4. **自清理机制**：若建群气泡发布 24 小时后，聊天室人数 ≤ 2（含发起人），自动解散，气泡同步消失

- **安全保障**：在需要帮助时（如夜间独自回家），能快速向附近的人发出安全请求。
- **专属记忆**：通过"私密气泡"记录个人足迹和回忆，形成自己的"城市日记"。

4. **自清理机制**：若建群气泡发布 24 小时后，聊天室人数 ≤ 2（含发起人），自动解散，气泡同步消失

适合：音乐节拼车、漫展同好、校园活动临时小组、citywalk 临时团。

### 3.6 地图与定位机制

#### 三种使用状态

| 状态 | 中心点 | 默认范围 | 适合 |
| --- | --- | --- | --- |
| **默认状态** | 你的真实 GPS 位置 | 5 公里 | 下班路上随便看看附近有啥 |
| **搜索定位** | 你搜的地点或活动（如"草莓音乐节"） | 可调 | 周末想重点看某场活动 |

（搜索定位当前只接入了腾讯地图的地点搜索api，后期可以接入活动标注功能，允许通过商家/活动/官方认证的账户设置活动气泡/活动标点）

#### 3.7 局域可见范围

你随时可以调整可见范围：

```
100 ~ 5000 米，每 100米 一档
```

调整后，**地图上会有一个可视化的圆圈**实时显示你的可见边界（局域）——这是"此刻地图"的独家设计，让你对"我能看到多远的气泡信息"有清晰认知，避免误判。

#### 典型使用场景

- **下班路上看一眼**：保持默认状态，看 5 公里内有没有小展、路演、市集
- **周末去特定活动**：搜索"草莓音乐节"→ 地图飞过去 → 选 1 公里范围 → 看场地内拼车、排队、见闻
- **在商圈逛街**：搜索"XX 商圈"→ 选 500 米范围 → 重点看这片区域里别人的推荐与避雷
- **校园内活动**：定位到"XX 大学 XX 校区"→ 选 1 公里范围 → 看校内求助、组队、失物招领

### 3.8 社交互动

#### 基础互动（在气泡详情页）
- 点赞 / 收藏 / 评论 / 转发
- 一键向发布者**发起私聊**
- 互为好友后，可在**收件箱**中发起好友群聊

#### 加好友
- 在别人头像 / 气泡详情里点"加好友"
- 对方在**收件箱**收到申请
- 同意后出现在你的好友列表

#### 创建群聊（好友群）
- 私聊界面右上角 **+**
- 选好友 → 创建
- 群消息所有人实时收到

#### 加群聊天室（建群气泡）
- **无需加好友**，点击气泡即进入

### 3.9 筛选与发现

气泡多了怎么办？用 **"范围 + 标签"** 双重筛选：

1. **调整范围**：缩到 100 米看眼前；放到 5 公里看周边
2. **按气泡类型筛**：只看"组队"、只看"推荐"、只看"避雷"

> 未来考虑
> 1. 引入简单推荐逻辑，根据你的兴趣优先展示相关气泡。
> 2. 设计紧急类型气泡，此类气泡将通过应用消息/短信/邮件的形式广播附近的志愿者用户（同意加入志愿者计划的用户，保障隐私），促进构建互帮互助的社会

## 4. 典型场景示例

### 场景 1：音乐节

> 你一个人去草莓音乐节，结束后想找附近的人拼车回市区。

1. 打开"此刻地图"，搜索"草莓音乐节"→ 定位过去
2. 选 1 公里范围，看到所有场内气泡
3. 找到有人发的 **🤝 组队** 气泡"东门拼车回市区，还有 2 个座位"
4. 点击进入 **💬 私聊** 协商具体时间地点
5. 或者有人发了 **💬 建群** 气泡"散场拼车群" → 直接进群喊一声

### 场景 2：逛漫展

> 你在漫展看到一个超棒的 coser 想合影，但身边没朋友。

1. 发布一个 **👀 见闻** 气泡"求 coser 合影搭子，A 馆"
2. 几秒后，附近的人看到，可能直接发 **🤝 组队** 回应你
3. 或者直接进一个"漫展搭子" **💬 建群** 聊天室

### 场景 3：临时求助

> 你在一个陌生商圈突然内急，找不到厕所。

1. 发布一个 **🆘 求助** 气泡"求最近的公共厕所位置！急！"
2. 附近的人看到会回复具体位置（公开气泡是所有人可见）
3. 完事后记得把气泡设为**私密**，作为个人记录保存

### 场景 4：citywalk

> 你和朋友约了周末去老城区 citywalk，但朋友临时有事。

1. 发一个 **🤝 组队** 气泡"周日下午老城区 citywalk 缺 1 个搭子"
2. 几小时内，可能会有同好看到并回应
3. 也可以直接建 **💬 建群** 气泡"老城区 walk 临时群"，让感兴趣的人先进来聊

### 场景 5：校园十大歌手

> 学校有十大歌手决赛，你想找同学一起去看。

1. 定位到学校，1 公里范围
2. 发 **🤝 组队** 气泡"今晚十大歌手有人一起吗？B 区座位"
3. 也可能看到别人发的 **⭐ 推荐** 气泡"演出 8 点开始，建议提前 1 小时到场"

### 场景 6：校园失物招领

> 你下课回宿舍路上发现教学楼 3 楼有同学落下了一个黑色钱包，喊了一声没人应。

1. 打开"此刻地图"，定位到"XX 教学楼"，范围 100 米
2. 发一个 **🆘 求助** 气泡"教学楼 3 楼 305 门口捡到一个黑色钱包，失主看到请私聊认领"（带 1 张图）
3. 失主（或知情同学）看到后会直接发起 **私聊** 跟你联系

## 6. 技术栈

| 层 | 技术 |
| --- | --- |
| 前端 | 原生 HTML / CSS / JavaScript（ES6，无框架，无构建工具） |
| 地图 | 腾讯地图 JavaScript API v2.exp + 浏览器 Geolocation API |
| 图片裁剪 | Cropper.js 1.6.2（CDN） |
| 后端 | Node.js + `ws` 库（WebSocket 全双工长连接，无 HTTP 框架） |
| 数据库 | SQLite 3（`sqlite3`，初期零配置单文件，后续可迁移 MySQL） |
| 服务器 | 阿里云 ECS（云服务器） |
| 监控面板 | 纯 HTML 模板字符串（端口 3001） |
| 部署 | Vercel（前端静态）+ 自建 Node 服务器（后端） |
| Android | Android Studio WebView 嵌入，`sync-android.bat` 同步 |
| 小程序 | 计划中 |
| 版本控制 | Git + 10 分钟自动提交脚本 `auto-git.bat` |

### 6.1 系统架构

前后端分离架构：

```
浏览器（H5 单页应用）
    │
    ├── 腾讯地图 JavaScript API（地图渲染）
    ├── WebSocket ←──────────→ Node.js 服务端
    │                                │
    │                          ┌─────┴─────┐
    │                          │   SQLite  │
    │                          └───────────┘
    └── Geolocation API（GPS 定位）
```

### 6.2 核心技术要点

| 技术点 | 实现方式 | 说明 |
| --- | --- | --- |
| 实时通信 | WebSocket 全双工长连接 | 毫秒级双向同步，满足即时交互需求 |
| 地理围栏推送 | 服务端遍历在线用户，计算距离后精准推送 | 信息只推送给最相关的人 |
| 位置服务 | 腾讯地图 API + Geolocation API | 高精度定位，支持手动选点或自动定位 |
| 可见性动态刷新 | 每 5 秒根据位置、范围重新计算可见性 | 减少地图渲染负担，仅渲染可见范围内的用户和气泡 |
| 前端状态管理 | `js/globals.js` 统一全局变量 | 25 个 JS 文件共享同一状态池 |

### 6.3 异常处理与降级策略

| 异常场景 | 处理方式 |
| --- | --- |
| **网络断开** | WebSocket 自动重连，重连后重新发送登录信息和位置，恢复状态 |
| **定位失败** | 根据错误码给出精准提示，回退至默认坐标（上海东方明珠），提供手动选点模式 |
| **地图加载失败** | 控制台报错，非地图功能（聊天、登录、个人中心）正常使用，提示用户刷新重试 |

## 9. WebSocket 消息协议

前后端通过 WebSocket 通信（端口 3000）。客户端 `socket.send(JSON.stringify({ type: "xxx", ... }))`，服务端按 `data.type` 分发。

消息类型分类（**共计 60+ 种**，详见 SERVER.js）：

### 认证 / 用户
* `register` / `authLogin` / `login` — 注册与登录
* `queryUserByIdOrPhone` — 按 ID 或手机号查用户
* `getUserFullInfo` / `getUserCenterData` — 拉取用户完整信息
* `updateUserInfo` / `updateAvatar` — 修改资料
* `queryVipStatus` / `activateVip` — VIP 状态

### 气泡
* `publishBubble` / `updateBubble` — 发布 / 修改气泡
* `queryBubbles` — 按位置查附近气泡
* `queryBubbleInteraction` — 查气泡的点赞/收藏/评论状态
* `likeBubble` / `favoriteBubble` / `commentBubble` — 互动
* `queryBubbleComments` — 评论列表

### 个人中心
* `getUserCenterData` — **一次性拉取** 个人中心所有数据
* `queryUserStats` / `queryUserPublished` / `queryUserLikes` / `queryUserFavorites` / `queryUserComments` / `queryUserViews` — 独立查询
* `searchRecords` — 个人中心内搜索
* `deleteRecords` — 删除记录

### 通知 / 私聊 / 群组
* `queryInboxUnread` / `queryNotificationsByType` / `markNotificationRead`
* `sendPrivateMessage` / `queryPrivateChats` / `queryPrivateMessages` / `queryPrivateUnreadCount`
* `sendFriendRequest` / `acceptFriendRequest` / `rejectFriendRequest` / `queryFriends` / `queryFriendRequests`
* `createGroup` / `queryMyGroups` / `queryGroupMembers` / `sendGroupMessage` / `queryGroupMessages` 等

### 位置 / 通讯
* `position` — 上报位置
* `publicChat` / `chatroomMsg` — 公屏与聊天室
* `privateChat` — 私聊

### 地点服务
* `getProvinces` / `getCitiesByProvince` / `searchCities` — 行政区
* `searchPlaces` / `reverseGeocode` — 关键词搜索 / 逆地理编码

### 管理
* `adminCommand` / `clearBubbles` — 管理员指令

## 10. 本地部署

### 10.1 本地开发

```bash
# 安装依赖
npm init -y
npm install ws sqlite3

# 启动后端（WebSocket 端口 3000 + 监控大屏 3001）
node SERVER.js

# 前端：直接用浏览器打开 index.html
# 或本地起一个静态服务器
npx serve .
```

### 10.2 调试模式

```bash
# 开启详细日志（默认关闭，抑制高频 console.log）
DEBUG_WS=1 node SERVER.js

# PM2 模式
DEBUG_WS=1 pm2 restart SERVER

开启 `DEBUG_WS=1` 后，下面这些日志才会输出：

* `📍 xxx: 经纬度 (范围)`
* `🔍 查询气泡: xxx 找到 x 个`
* `📊 查询统计数据` / `📊 查询发布记录`
* `📨 收件箱未读: xxx`
* `📍 后端逆地理编码`

### 10.3 本地全栈部署（前后端一体）

将项目在本地跑通需要修改 `js/websocket.js`：

**第 19 行** — WebSocket 连接的目标地址：

```diff
- const SERVER_IP = '121.199.161.5';  // 服务器外网IP
+ const SERVER_IP = 'localhost';      // 本地部署改为 localhost
```

**第 24–27 行** — 本地环境不再跳转到外网：

```diff
- if (hostname === 'localhost' || hostname === '127.0.0.1' || hostname === '') {
-     host = SERVER_IP;
- } else if (hostname === SERVER_IP) {
+ if (hostname === 'localhost' || hostname === '127.0.0.1' || hostname === '' || hostname === SERVER_IP) {
+     host = SERVER_IP;
```

> **注意**：腾讯地图 SDK 需要联网加载（`https://map.qq.com/api/js`），本地开发需保持联网。

```bash
# 启动后端（端口 3000）
node SERVER.js

# 另开终端，启动前端静态服务（端口 5500 或其他）
npx serve . -p 5500
```

浏览器访问 `http://localhost:5500/index.html`，右上角状态显示 ✅ 已连接即表示前后端联通正常。

#### 已知本地限制

| 限制 | 原因 | 对策 |
| --- | --- | --- |
| 腾讯地图 SDK 必须在联网环境加载 | SDK 从 CDN 加载 | 开发时保持联网 |
| WebSocket 默认端口 3000 可能被占用 | 其他进程占用 | `taskkill /F /PID <pid>` 或修改端口 |
| 地址搜索依赖外网 | 后端调用第三方 API | 本地开发搜索可能无效，不影响登录/气泡 |
| 数据库文件 `users.db` 与 `SERVER.js` 同目录 | SQLite 文件写入 | `gitignore` 建议忽略 `users.db` |

### 10.4 部署

* **前端静态文件**：部署到 Vercel（`vercel.json` 把 `/api/*` 代理到后端 `http://121.199.161.5:3000`）
* **后端 + WebSocket**：部署到 `121.199.161.5:3000`（自建）
* **监控大屏**：`http://<server>:3001/` 提供清除气泡、强制下线按钮
